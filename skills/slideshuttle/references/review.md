# 视觉审美复核与改稿清单

`build.py` 编译通过只代表“没有语法错误和机械溢出”。**在向用户交付前，必须满足两部分审核：一是 `build.json` 中的 `designAudit` 零警告，二是亲自用读图工具逐页查看 PNG 完成视觉审查。**

---

## 一、 五维视觉审美评分表（逐页对照 PNG 复核）

先看 `contact-sheet.png` 检查全稿节奏，再逐张查看 `preview/slide-*.png` 原图：

| 审核维度 | 合格标准（Pass） | 不合格特征（Fail → 必须返工） | 具体改法 |
|---|---|---|---|
| **1. 3 秒焦点测试** | 第一眼立刻看到本页的唯一主角（大数字、核心图或主公式），标题一句话说清判断 | 满屏都是差不多大的方框和文字，视线不知道往哪落 | 放大核心证据（占 50%+ 面积）或提取一个 `72px+` 关键指标，弱化次要说明 |
| **2. 呼吸感与留白** | 画布边缘和模块之间留白充裕（≥ 40%），底部干净无页码/页脚噪音 | 盒子贴盒子、大框套小框（Box-in-Box），或底部默认塞了“第 X/Y 页”及工具水印 | 删掉外层多余边框、底色与页码页脚，将并列卡片减至 ≤ 3 个，增大 `padding` 和 `gap` |
| **3. 字号与文风** | 正文 `20px–26px` 清晰易读，每条要点 1–2 行短语，无冗余口水话 | 出现 `< 18px` 的密麻小字，或超过 3 行的自然段 | 把长句砍成短语，把推导过程移入 `<Notes>`，或将 1 页拆为 2 页 |
| **4. 排版细节与断词** | 换行自然，标题与短标签无孤字，图标/文本垂直对齐干净 | 出现“发出提 / 问”、“亮出标 / 签”等跨行拆词，或末尾多出单字孤行 | 润色精简 2–4 个字，或微调列宽与 `white-space:nowrap` |
| **5. 全稿色彩与节奏** | 全稿共享统一的墨色、底色与 1–2 个强调色；连续页面构图有张弛变化 | 单页五颜六色（红黄蓝绿框同屏），或连续 4 页都是相同的三列卡片 | 统一全稿 `Token` 色板，将重复的卡片页改为左右对比、大图解或大字强调页 |

## 二、 常见诊断与审计警告的修复优先级

当 `check` 或 `designAudit` 报错/警告时，**严禁靠缩字号偷懒**，按以下顺序处理：

1. **`slide_too_dense`（单页可见字数 > 200 字） / `paragraph_too_long`（单节点行数过多）**
   - **原因**：把讲稿写进了画面。
   - **修复**：删去所有解释性从句和连接词，只留核心短语；把完整解释挪进 `<Slide>` 底部的 `<Notes>`；若一页包含两个独立子话题，拆成两张 Slide。
2. **`font_too_small`（字号 < 16px） / `body_font_small`（正文字号 < 20px）**
   - **原因**：在 `design.xml` 或行内样式里设了过小字号。
   - **修复**：将正文字号恢复至 `20px–24px`、图注恢复至 `16px–18px`，同时配合第 1 条削减字数。
3. **`visual_clutter`（单页渲染节点 > 22 个）**
   - **原因**：使用了过多装饰性色块、嵌套容器或把本可用 3 个节点表达的图示拆成了 20 个零碎形状。
   - **修复**：合并文字与标签，去掉不必要的背景框，保持每页结构简洁有力。
4. **`text_overflow` / `text_tight`（文本溢出或宽度余量 < 3%）**
   - **原因**：文本实际排版宽高超出了固定 `height` / `width`。
   - **修复**：优先精简文案字数；其次给文本框增加 `height` 或 `width`。
