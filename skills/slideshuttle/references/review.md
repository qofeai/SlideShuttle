# 复核：看图改稿

构建之后读。编译通过不代表视觉验收；交付前修复编译错误，并用读图工具查看每一页。`designAudit.warnings` 是需要结合用途检查的可读性风险，`hints` 是风格建议，两者都不要求机械清零。

## 1. 先看全稿

1. **标题测试**：读 `outline.md`。只读标题能复述整个论证吗？有没有主题词标题、重复的判断、跳过的步骤？不通过就回到 `brief.md` 改故事线，然后才动版式。
2. **节奏**：看 `contact-sheet.png`。缩成小图后每页还能认出主角吗？底色和疏密有没有变化？有没有连续几页长得一样？标题位置是否一致？

## 2. 再看每页原图

| 看什么 | 不合格的样子 | 改法 |
|---|---|---|
| 焦点 | 眯眼看时，最重的色块不是主角；满屏是差不多大的框和字 | 放大主角，弱化其余内容，删掉装饰框 |
| 论断与证据 | 图表或数字证明不了标题；大数字只是复述最大值 | 改标题，或者换一个能直接证明标题的证据，绝不改数据 |
| 留白 | 内容挤在上半页、下面空一截；卡片里字少、空白多；大框套小框 | 主体用 `flex-grow` 占满并锚定，去掉 Text 的固定 height 和多余的框 |
| 文字 | 小字、自然段、跨行拆词（“发出提 / 问”）、行末孤字 | 删词改成短语，移进讲稿，微调列宽，或者拆页 |
| 排版 | 行太长、行距过紧、标题在词中间断开、不同文字之间挤在一起、标点或数字格式不合受众的惯例、对比度不够 | 按 [design.md](design.md) 第 3 节逐条处理 |
| AI 味 | 出现 [design.md](design.md) 第 5 节列出的特征 | 按那张表处理 |

有动画的页，用 `render --steps` 逐步看：每次点击只多出一组相关内容。

## 3. 诊断与审计警告

| 代码 | 通常原因 | 修复 |
|---|---|---|
| `slide_too_dense`、`paragraph_too_long` | 把讲稿写进了画面 | 删去从句和连接词，解释移进 `<Notes>`；两个话题就拆成两页 |
| `font_too_small`、`body_font_small` | 为了塞字缩小了字号 | 恢复字号，同时删减文字 |
| `visual_clutter` | 装饰块、嵌套容器、零碎形状太多 | 合并、去框 |
| `unwanted_page_number_or_footer` | 加了用户没要求的页码或页脚 | 删掉 |
| `text_overflow`、`text_tight` | 文字超出了固定尺寸 | 先精简文字；去掉 Text 的固定 height；最后才放大容器 |
| `line_too_long` | 多行文字铺满了很宽的栏 | 收窄栏宽（改分栏比例），或者精简到一两行 |
| `tight_leading` | 行高比例过小 | 加大 line-height；字形高或带附加符号的文字取更大值 |
| `low_contrast` | 为了降级次要信息而把颜色调淡 | 加深颜色，改用字号和位置来降级 |
| `type_scale_sprawl` | 各页随手写字号，字号级数失控 | 合并相近的字号，统一用 Style 引用 |
| `palette_review`（提示） | 源码定义了多种饱和色，脚本无法判断语义 | 检查分类、状态和品牌色是否一致；合理多色保留，不必改成灰色 |
| `title_position_shift`、`missing_title`（提示） | 标题位置变化或没有标题 | 检查是否有意；章节页、图片页可以例外。有标题时用 `id="title"` 方便提取 |

`designAudit.hints` 里的 `text_fixed_height`、`missing_notes` 不阻断交付，但通常是“底部空一截”和讲稿缺失的原因，要逐条确认。

改完用新目录重新构建，复核改动过的页；改了共享的 Token、Style 或 Component，就复核所有用到它的页。

## 4. 交付说明

默认只附上 `build.json.deliverables` 中的一个 QPPT。源文件、总览、PNG、大纲和审计日志留在内部，不打包发送。只有用户明确要求时才导出并附上其他格式。简短说明内容和实际验证范围；不要把内部审计报告当成交付附件。原生 PNG/PDF 只代表原生引擎的渲染效果。
