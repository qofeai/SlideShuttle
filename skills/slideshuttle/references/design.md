# 将网页设计能力转为演示编排

## 从信息关系选构图

把每页当作固定画布上的一段视觉论证。标题负责观点，主体给证据或关系，辅助信息解释上下文。可以用短设计说明约束全稿：受众需要做什么判断、哪些内容最重要、用什么视觉语气传达。用户已有品牌或模板时，以其规则为准。

| 内容关系 | 可用构图 | 检查重点 |
|---|---|---|
| 核心主张 / 开场 | 大标题与单一主视觉、不对称分区、留白 | 观众先看到主张；装饰服务主题 |
| 现状与变化 | 前后对照、大小对照、跨列强调一个差异 | 两边基线、单位、时间范围一致 |
| 数值和证据 | 大图表加紧邻的结论或关键数字 | 图表回答标题的问题，单位和来源可见 |
| 选择与取舍 | 按同一维度对齐的比较、紧凑表格 | 最有区分度的维度占据主要空间 |
| 流程 / 因果 | 方向明确的路径、阶段、分支 | 箭头表达真实关系，顺序读得通 |
| 分组 / 结构 | 少量分区、层级、一个中心与支撑项 | 同类靠近、层级一致，而非所有块等重 |
| 决策 / 收束 | 结论突出，配行动、负责人或下一步 | 观众知道需要做什么 |

这些是可组合的表达方式，不是必须填满的页型清单。一个复杂观点可以拆成多页；简短材料也不必凑出一整套模板。保持同一设计语言，同时按叙事需要改变密度和构图。

## 借鉴网页，而不是依赖浏览器

| 网页设计习惯 | 在 SlideShuttle 中表达 |
|---|---|
| 设计令牌与类型尺度 | Token + Style，颜色、字号、间距成体系 |
| Grid 的内容列 / 侧栏 | Box + 显式 grid-template-columns，主要证据优先分配空间 |
| Flex 的对齐与剩余空间 | display:flex、gap、align-items、flex-grow/basis/min-width |
| 复用组件 | Component / Use，语义稳定的 ID |
| Hero、编辑式分栏、标注 | 标题、主体与支持区域；装饰可 absolute |
| 图层与透明色 | 叶子 Shape/Path 或 RGBA 色；容器不支持整体透明度 |

原生语言无需把每个元素变成绝对坐标。让内容关系进入容器；对需要精确标注、装饰或几何图示的区域使用定位。优先保留能修改的文本与数据，图片用于图像本身。

## 好用的起点，可按内容调整

默认 1280×720，边缘留 48–64px，段落/区域间距可从 16/24/32/48 的节奏起步。标题约 40–64px、正文约 22–28px、注释约 16–18px 是常见起点；阅读型密集稿和用户指定模板可以另设尺度。所有数值都要以实际字体和输出用途为准。

色彩优先建立背景、主文字、次级文字和强调色的职责。强调色用于证据和动作，不要求每页都有大色块。对比要让主要信息容易读，次要说明也不能因太浅而失读。

先分配标题、主视觉和证据的位置，再填细节。给主要图表足够面积，标注靠近对应数据。图表不必机械居中，数据页也不必配一个装饰插画。

正文装不下时先处理信息结构：消除重复、压缩表述、拆分论点、改变列宽或拆页。确认关键事实仍在，再考虑字号和行距。空白是关系的一部分，不以把每个角落填满为完成标准。

## 改善全稿节奏

在总览里看哪些页承担开场、证据、解释和收束。若连续几页都像同一张卡片模板，判断是否能把其中一页改成更适合内容的图表、对照或关系图；不为变化而打乱品牌与阅读习惯。共享对齐线、字体和颜色，让变化仍像同一份稿。
