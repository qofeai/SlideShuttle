# 设计：从故事线到画布

写 `brief.md` 和 `design.xml` 之前读一遍。代码片段都来自 [assets/starter/](../assets/starter/deck.xml)，已经编译并逐页查看过。

## 1. 故事线

**场合决定密度。** 现场讲：突出判断和视觉证据，补充说明放 `<Notes>`。发给人读：画面应保留理解所需的定义、推导和来源。教学可按问题展开，品牌展示可让图片主导。两者都有时明确主要用途，不假设读者会打开讲稿。字号、页数和留白共同调整，以实际阅读效果为准。

**结构。** 复盘、汇报、提案默认结论先行，第 2 页就给答案，后面每页支撑答案的一部分。需要说服时用 SCQA：情境 → 冲突 → 问题 → 回答。关键转折单独给一张呼吸页。最后一页写清谁在什么时候要决定什么、代价是多少，而不是写“谢谢”。

**标题帮助读者定位。** 汇报与提案优先用简短论断；课程、目录、作品展示可用主题或问题。数字、方向和对象有助于具体表达，但不要为了标题形式编造结论。

| 汇报主题 | 可用的论断写法 |
|---|---|
| 市场分析 | 华东增速放缓，但客单价仍领先 18% |
| 技术架构 | 把检索移到边缘节点，延迟从 420ms 降到 90ms |
| 下一步计划 | Q4 分三步，把首月激活带到全部门店 |

- 标题必须和证据一致：标题说“第 4 周起拉开”，曲线就要在第 4 周出现拐点。对不上就改标题，不能改数据。
- 封面可以写结论，也可以保留用户给定的课题、活动或品牌名称。
- 大数字页把数字和句子写进同一个 title（数字用 Span 放大），这样 `outline.md` 里读到的是完整的一句。

**改写材料。** 按判断重新排序，不按原文段落逐段搬运；每个判断只把最强的一条证据放上画面；删掉“因为”“我们可以看到”这类连接词；数字保留单位、口径和时间，来源用一行 16px 文字写在证据旁边。

## 2. 画布骨架

```xml
<!-- design.xml -->
<Style name="page">width:1280px;height:720px;padding:56px 64px 72px 64px;display:flex;flex-direction:column;gap:40px</Style>
<Style name="body">flex-grow:1;flex-basis:0;min-height:0</Style>
<!-- pages/03-evidence.xml -->
<Box id="frame" class="page">
  <Text id="title" class="title">第 4 周起，会员与非会员的复购差距持续拉开</Text>
  <Box id="grid" class="body" style="display:grid;grid-template-columns:8fr 4fr;gap:56px">
    <Chart id="chart" … style="height:100%">…</Chart>
    <Box id="reading" style="display:flex;flex-direction:column;justify-content:flex-end;gap:20px">…</Box>
  </Box>
</Box>
```

- **Text 默认不写 height**，让引擎按内容测量；固定占位确有需要时可使用 height，检查文字是否完整。
- 在主体里用对齐决定内容落在哪里：`flex-end` 锚定到底部（封面、大数字页、收束页），`center` 居中（数字行、时间轴），`space-between` 上下分开。
- 网格：左右边距 64，12 栏、栏距 24。分栏用 `8fr 4fr`、`7fr 5fr`、`5fr 7fr` 这样的非对称比例；等分只给真正并列的内容。内容页的标题始终在同一个位置。
- 从少量字号层级起步，按标题、正文、注释等职责复用。复杂报告可增加层级，不强求固定倍率。颜色 Token 按职责命名，如 `ink`、`muted`、`accent`、`series-a`、`success`；多系列图表和品牌色可以超出一个强调色。

## 3. 文字排版：各语言通用的原则

排版规则来自读者的眼睛和所用文字的书写系统，而不是某一种语言的习惯。先按通用原则做，再按所用文字的惯例调整。

1. **行长按 em 计，不按字符数。** 多行正文的行长以 em（字号的倍数）计，参考值见 SKILL.md。30em 大约相当于中日韩 30 个字、拉丁字母 60 个字符；现场幻灯片的正文通常更短。行太长时，眼睛很难找到下一行的开头。
2. **行高跟着字号和字形走。** 正文约 1.4–1.6 倍；字形高、笔画密或上下有附加符号的文字（中日韩、泰文、天城文、越南文）取上限甚至更高；标题约 1.1–1.3 倍；超大数字约 1.0 倍。字越大，行高比例越小。
3. **对齐从阅读起点开始。** 正文按阅读方向起点对齐（从左到右的文字靠左，从右到左的文字靠右）。居中只给短的展示文字。两端对齐只在适合的文字和足够宽的栏里用：中日韩方块字可以两端对齐；拉丁字母窄栏两端对齐会出现大片空隙，不要用。
4. **按意思断行。** 标题和展示文字手动在词组或意群边界换行，不让一个单字或单词独占一行，不把数字和单位、姓和名、否定词和它修饰的词拆开。
5. **尊重所用文字的断行规则。** 中日韩：句号、逗号、右括号不在行首，左括号不在行尾（引擎已经处理）。拉丁字母：不在词中间断开，不依赖自动断字。泰文、老挝文、高棉文词间没有空格，换行位置要人工确认。
6. **不同文字混排要协调。** 选字面大小、笔画粗细、灰度相近的字体搭配；中日韩与拉丁字母、数字之间留约 1/4 字宽的间隙（引擎不会自动加，用一个空格或 `letter-spacing` 处理）；所有字符都要在提供的字体里有字形。
7. **标点、数字和格式按当地惯例，并且全稿一致。** 引号（“” 「」 « » „“）、千位分隔符、小数点、日期与货币格式、数字和单位之间的空格，都按受众所在地的惯例写。表格里的数字列按小数点对齐，同一列使用同样的精度。
8. **强调方式要有职责。** 字重、颜色、大小可以配合使用，避免每句话都强调。只使用实际提供的字重和字形，不依赖引擎合成斜体。字距按所选字体和实际预览调整。
9. **阅读方向决定版面方向。** 从右到左的文字（阿拉伯文、希伯来文）整页镜像：标题和阅读起点在右侧，时间轴与流程从右向左走。引擎能正确连写和排序，但默认靠左对齐，要显式写 `text-align:right` 并镜像布局；数字和嵌入的拉丁字母仍然从左到右。
10. **对比度要够**（参考值见 SKILL.md）。次要信息可以靠字号和位置降级，避免颜色淡到看不清。

## 4. 按信息关系选构图

| 关系 | 构图 | 示例页 |
|---|---|---|
| 开场、收束 | 深色满版，大标题锚定左下，元信息在顶部 | `01-cover` |
| 结论先行 | 标题加 2–3 个关键数字，共享一条基线；只有需要行动的那个数字用强调色 | `02-summary` |
| 数据证据 | `8fr 4fr`：大图表加侧栏，呈现读数、含义和来源；分类用稳定配色，灰色可用于弱化背景系列 | `03-evidence` |
| 转折、单一事实 | 强调色满版，一个 200px 以上的数字加一句话 | `04-gap` |
| 流程、时间 | 一条线穿过 3–5 个节点；日期写在圆点下方，不与线并排 | `05-plan` |
| 对照、取舍 | `1fr 1fr` 或 `5fr 7fr`，同一维度逐行对齐，旧方案用灰色 | — |
| 概念、公式、架构 | 大公式或关系图占 55–60% 面积，旁边 2–3 条短语拆解 | — |
| 决策、请求 | `5fr 7fr`：左边是请求，右边是选项和代价 | `06-decision` |

**全稿节奏**：底色的切换要有理由（封面和收尾用深色、转折用强调色、证据用浅色）；疏密交替，不要连续 3 页都是中高密度；连续两页不用完全相同的版式。

## 5. 一眼就像 AI 生成的特征

| 特征 | 改法 |
|---|---|
| 每页顶部一个英文小标签，如 `01 / KEY INSIGHT` | 删掉 |
| 内容堆在上半页，下面空一截 | 主体用 `flex-grow` 占满并锚定；去掉 Text 的固定 height |
| 三四个等宽卡片并排，卡片里字少、空白多 | 找出主角放大，其余改成无框的批注 |
| 每张卡片都有彩色顶线，每个标题前都有图标 | 去掉装饰 |
| 大数字只是复述图表里的最大值 | 换成差值、倍数或变化，也就是图表要证明的那个结论 |
| 页面上写着“示例数据”“仅供参考” | 移进讲稿 |
| 一页里同时出现两套编号（`01` 加 `A/B/C`） | 只保留一套，或者干脆不编号 |
