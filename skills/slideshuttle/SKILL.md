# 用 SlideShuttle 设计演示稿

先判断演示稿是供现场讲解、独立阅读、教学还是品牌展示，再安排密度与视觉风格。用户提供的品牌、尺寸和参考稿优先。按顺序处理三层：

1. **内容**：有清楚的阅读顺序，标题与证据相符，必要定义和来源不丢失。
2. **画布**：读者能辨认信息主次，文字、图表和图片的空间符合内容需要。
3. **系统**：字体、颜色和对齐有一致的职责，允许封面、章节页与内容页有不同版式。

## 质量要求与设计建议

缺字、资源缺失、意外裁切和错误数据必须修复。审美偏好不作为编译或交付条件。

未指定时以 1280×720 为起点。下表是现场演讲稿的参考，不是所有文稿的上限或固定比例。阅读型报告可提高密度，教学稿可保留推导，多系列图表、品牌展示可使用多色。`designAudit` 提供可读性警告和风格提示，需结合场景复核，不要求清零。

| 项 | 标准 |
|---|---|
| 字号 | 标题 40–52px、正文 20–26px、图注 16–18px 起步；根据画布、观看距离和信息职责调整，按实际预览确认可读 |
| 密度 | 演讲页尽量短；超过约 220 字或单框 7 行时复核是否应拆页。报告和教学不机械套用这个阈值 |
| 留白与结构 | 成块留白、清楚分组；复杂关系可以有更多节点，不用固定节点数或留白百分比代替判断 |
| 焦点 | 让主张或关键证据容易找到；比较、矩阵和多图分析可有多个相关焦点 |
| 排版 | 参考 32em 内的多行行长、正文 1.25 倍以上行高；复用字号和对齐。页面有标题时用 `id="title"` 方便提取大纲 |
| 颜色 | 建立主色、辅助色和分类/状态色的职责，同一语义保持一致；允许多色，不限制强调色数量。检查文字对比度，通常以正文 4.5:1、大字 3:1 为参考 |

放不下时先检查内容和空间分配，再考虑拆页或调整字号。现场讲解的补充说明可以放 `<Notes>`；供独立阅读的关键定义和口径应保留在画面中。

## 流程

**1. 简报**：先读 [design.md](references/design.md)，在工程目录写 `brief.md`：用途、受众语言和地区、要传达的信息、页序和视觉方向（模板见 [assets/starter/brief.md](assets/starter/brief.md)）。缺少影响结论的事实时集中问用户；非关键偏好做合理假设。

**2. 源稿**：按多文件工程写，语法遇到问题查 [syntax.md](references/syntax.md)。

```
deck/
  brief.md        # 简报与页面计划
  deck.xml        # 尺寸、字体、<Library src="design.xml"/>、按序排列的 <Slide src>
  design.xml      # Token / Style / Component：网格、字号阶梯、颜色职责、重复结构
  pages/01-cover.xml …
```

先定 `deck.xml` 和 `design.xml`，再写页面。可复制 [assets/starter/](assets/starter/deck.xml) 起步，但要按内容调整主题和构图；这份商务复盘模板不是唯一风格。

**3. 构建**：

```bash
python3 scripts/build.py --doctor
python3 scripts/build.py deck/deck.xml --out out/v1
```

默认交付文件是 `out/v1/deliverables/presentation.qppt`，字体已按用字裁剪。逐页 PNG、总览、大纲和 `build.json` 留在工程里用于内部复核。编译错误必须修复；设计警告逐项评估，不为清零而破坏合理设计。`--strict-design` 仅在明确需要可读性警告阻断时启用，风格提示始终不阻断。

只有用户明确要求其他格式时才加 `--export pptx` 或 `--export pdf`，两者可重复组合。QPPT 默认子集字体适合当前文稿的离线显示；新增字符后在有完整字体的创作环境重新打包。用户明确需要离线任意加字的完整字体包时使用 CLI `pack --full-fonts`，并说明体积代价。

**4. 复核与交付**：按 [review.md](references/review.md) 读大纲、看总览和逐页 PNG；改稿用新目录（`v2`）构建。只上传/附上 `build.json` 的 `deliverables` 清单，默认恰好一个 QPPT。不要附带源工程 ZIP、PPTX、PDF、预览图或检查日志，也不要把整个输出目录压缩交付；用户明确要求的附加文件除外。简短说明内容与实际验证范围即可。

## 边界

- 不悄悄改动原始事实和数字。演示数据、推测要标明，写在讲稿和简报里，不在页面上加免责声明。
- 没在 PowerPoint 或 WPS 里打开过，就不声称已通过 Office 验收。
- 已有 PPTX 要保留 `losses` 和基线，走 `diff` 逐项决策（见 syntax.md 第 3 节）；`.slide-shuttle/` 可能含历史正文，不作为交付附件。
